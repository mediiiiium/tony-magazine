## 1. 全体コンセプト・売り方の基本方針

### 1-1. 前提となる問題意識

受託がしんどくなる原因はスキル不足ではなく**商品設計**にある。

| 切り売り型（避ける） | 商品型（目指す） |
|---|---|
| 「1件ヒアリングして作ります」 | 「完成済みのものを設定して渡します」 |
| 見積もり・要件定義から毎回スタート | 価格・納品物・範囲が固定 |
| 納品後の質問対応が無限に伸びる | マニュアルが質問を吸収する |
| 売上 ＝ 稼働時間 × 単価（上限あり） | 売上 ＝ 販売本数 × 単価（上限なし） |

### 1-2. 基本方針：「商品 ＋ マニュアル」構成

納品物を必ず次の3点セットにする。これが崩れると即座に時間の切り売りに戻る。

1. **本体**（GASスクリプト / 静的化済みサイト / テンプレート）
2. **導入マニュアル**（スクリーンショット付き。初回設定を顧客が自分でできる粒度）
3. **運用マニュアル＋FAQ**（よくある質問を先回りで潰す。ここが利益率を決める）

> ポイント：マニュアルは「おまけ」ではなく**商品の主要部分**。
> マニュアルの質 ＝ サポート工数の削減量 ＝ 実質時給。

### 1-3. 価格帯の設計（3階層）

| 階層 | 内容 | 価格イメージ | 狙い |
|---|---|---|---|
| **入口**：ノウハウ/テンプレ販売 | 手順書・スクリプト本体のみ。設定は自分でやってもらう | 1,000〜5,000円 | 実績数・レビュー数を稼ぐ。工数ほぼゼロ |
| **主力**：導入代行パッケージ | 本体＋初期設定＋マニュアル。作業は定型化済み | 15,000〜50,000円 | 利益の柱。1件あたりの実作業を数時間に圧縮 |
| **上位**：カスタマイズ/保守 | 個別要件の追加開発、月額サポート | 個別見積 / 月額 | 単発を継続収入に変える |

入口商品でレビューを集め、主力商品に導線を引くのが基本の流れ。

### 1-4. 売り文句の作り方

技術名ではなく**顧客の損失**を主語にする。

- ✗「GASで業務を自動化します」
- ○「毎日30分の転記作業を、月1,000円未満のコストでゼロにします」
- ✗「Cloudflareに移行します」
- ○「サーバー代が毎月かかっているサイトを、表示速度を上げたうえで**永久0円**にします」

## 2. 軸①：GAS（Google Apps Script）ツール・パッケージ

### 2-1. GASを選ぶ理由

- **サーバー不要**：Googleアカウントさえあれば動く。顧客側のインフラ費用が0円
- **納品が軽い**：スクリプトをコピー ＋ トリガー設定だけで完了する形に持ち込める
- **Googleサービスと直結**：スプレッドシート / フォーム / Gmail / カレンダー / ドライブ
- **横展開しやすい**：1本作れば、業種を変えて文言だけ差し替えて再販できる

### 2-2. 商品案A：AI連携系（ChatGPT / Gemini API）

| 商品 | 中身 | 想定顧客 |
|---|---|---|
| スプレッドシートAI関数 | `=GPT("要約して", A2)` のようなカスタム関数。列一括処理対応 | 一般事務・マーケ担当 |
| レビュー/アンケート自動分析 | フォーム回答を自動で感情分類・要約・タグ付けしてシートに追記 | 店舗・EC・人事 |
| 記事/商品説明文の量産ツール | キーワード列を入れると本文案が生成される | ブロガー・EC事業者 |
| メール下書き自動生成 | 受信メールをトリガーに返信案をGmail下書きへ保存 | 個人事業主・営業 |
| 議事録要約Bot | ドライブに置いた文字起こしを要約してSlack/LINEへ通知 | 小規模チーム |

**納品設計の要点**

- APIキーは**顧客自身に取得してもらう**（取得手順を図解マニュアル化）
  → 自分のキーを使わせると従量課金を被り、赤字リスクが青天井になる
- スクリプトプロパティにキーを保存する方式にし、コード内に直書きしない
- モデル名・プロンプト文はシートの設定タブから変更できるようにする
  → 「文体を変えたい」という要望が仕様変更ではなく**顧客の操作**で片づく
- 実行回数・トークン消費の目安を明記（想定コストを事前に共有）

### 2-3. 商品案B：定常業務の自動化系（AI不要・安定して売れる）

| 商品 | 中身 |
|---|---|
| フォーム→自動返信＋台帳化 | 申込フォーム受付 → 自動返信メール → シート台帳 → 担当者へ通知 |
| LINE公式連携 | フォーム回答やシート更新をLINEへ通知。予約リマインドの自動送信 |
| 定期レポート配信 | 毎朝/毎週、シートを集計してPDF or メールで自動送付 |
| 請求書・見積書の自動生成 | シート1行 → Googleドキュメント差し込み → PDF化 → ドライブ保存 → 送信 |
| 在庫・予約管理シート | 重複予約の排除、在庫閾値でのアラート通知 |
| カレンダー連携 | シートの予定を一括でカレンダー登録／変更を双方向同期 |
| ドライブ整理 | 命名規則にそったフォルダ自動生成・ファイル自動振り分け |

AI連携より地味だが、**壊れにくく・説明が簡単で・値引き交渉されにくい**。
売上の土台はこちら側に置くのが安全。

### 2-4. 納品フロー（定型化する）

```
1. 事前ヒアリングシート（固定質問10問）に回答してもらう ← 通話しない
2. こちらでスクリプト設定＋シート雛形を用意
3. 顧客のGoogleアカウントで実行できる形にして共有
4. マニュアル（PDF or Notion）を渡す
5. 動作確認 → 納品。以降の質問はFAQへ誘導
```

**ヒアリングを固定質問化するのが最大の時短ポイント。**
「打ち合わせしましょう」を1回やった時点で利益率は半減すると考える。

### 2-5. 制約として先に伝えておくこと

- GASの実行時間上限（1回あたり最大6分程度）。大量データはバッチ分割が必要
- 1日あたりのメール送信数・トリガー実行時間にGoogle側の上限がある
- 共有ドライブ/組織アカウントの権限設定によっては動かない場合がある
- Googleの仕様変更で将来的に改修が必要になる可能性がある（後述の免責へ）

## 3. 軸②：WordPress → Cloudflare（静的化・無料化）

### 3-1. 提供価値（売り文句の核）

| 顧客の現状 | 移行後 |
|---|---|
| レンタルサーバー代が毎月1,000〜3,000円 | **サーバー代 永久0円**（Cloudflare Pages 無料枠） |
| 表示が重い／PageSpeedが低い | 静的配信＋CDNで**爆速化**（SEO・離脱率に直結） |
| WordPressの脆弱性・改ざんが怖い | 静的HTMLなので**攻撃対象がほぼ消える** |
| プラグイン更新・PHP更新の管理が面倒 | 更新作業から解放される |
| アクセス集中で落ちる | CDN配信で耐障害性が上がる |

年間コスト換算で「1.2万〜3.6万円/年の削減 ＋ 高速化 ＋ セキュリティ向上」。
移行費用が数万円でも**1〜2年で回収できる**という説明が刺さる。

### 3-2. 基本の移行手順

```
1. 現行WordPressの完全バックアップ（DB＋ファイル）
2. 静的化：WP2Static / Simply Static などで静的HTML書き出し
   （またはローカル環境で生成 → 出力物だけを使う）
3. 出力物をGitリポジトリへ格納
4. Cloudflare Pages に接続してデプロイ
5. 独自ドメインをCloudflareのネームサーバーへ変更（DNS切替）
6. リダイレクト設定・フォーム代替・404チェック
7. 表示・リンク・画像・SSLの最終検品
```

### 3-3. 動的機能の置き換え表

静的化で**必ず**論点になる部分。事前に置き換え先を提示できると強い。

| 元の機能 | 置き換え先 |
|---|---|
| お問い合わせフォーム | Googleフォーム / Formspree / Cloudflare Workers ＋ GAS（← 軸①と接続できる） |
| コメント欄 | 外部サービス（Disqus等）or 廃止 |
| サイト内検索 | 静的検索（Pagefind等）or Google カスタム検索 |
| 会員限定ページ | Cloudflare Access / 別途SaaS。**静的化では原則対象外** |
| ECカート | Stripe決済リンク / 外部カート埋め込み。**フル機能ECは対象外** |
| 予約システム | 外部予約SaaS埋め込み |
| 記事の更新 | 更新のたびに再書き出し＋再デプロイ（＝運用フローの説明が必須） |

### 3-4. 展開パターン

**パターンA：ノウハウ販売（在庫なし・工数ゼロ）**

- Brain / note / Tips で「WordPressサイトをサーバー代0円にする完全手順」を販売
- 価格帯 2,980〜9,800円
- 画面キャプチャを大量に載せ、つまずきポイント（DNS切替、混在コンテンツ、パーマリンク）を先回りで解説
- 購入者からの個別質問は**受け付けない**か、別料金と明記

**パターンB：半自動代行（主力）**

- 移行作業そのものを受託。ただし**作業を完全にテンプレ化**して1件2〜4時間に圧縮
- 価格帯 30,000〜80,000円（サイト規模で段階価格：〜50ページ / 〜200ページ / それ以上）
- 納品物：移行済みサイト ＋ 更新手順マニュアル ＋ 旧環境のバックアップ

**パターンC：継続（任意）**

- 記事更新の再デプロイ代行を月額制で提供（月3,000〜10,000円）
- ただし継続案件は再び時間の切り売りになりやすい。
  → **「更新は顧客が自分でできる」状態を標準納品にし、月額は例外**という設計を推奨

### 3-5. 事前に確認すべきチェック項目

- ページ数（見積もりの根拠。ページ数課金にする）
- 会員機能・EC・予約など動的機能の有無 → **あれば対象外 or 別途見積**
- 独自ドメインの管理権限を顧客が持っているか（DNS変更に必須）
- 記事更新の頻度（高頻度なら静的化そのものが不向きな場合がある）
- 既存の広告タグ・解析タグ・外部埋め込みの数

## 4. 運用上の重要注意点（時間の切り売り化を防ぐ）

ここが本メモの本題。**商品自体より、範囲の線引きが利益を決める。**

### 4-1. サポート範囲を明文化する（出品文にそのまま載せる）

```
【本商品に含まれるもの】
・納品時点で動作するツール本体一式
・導入マニュアル（図解付き）／運用マニュアル・FAQ
・納品後 ◯日間の初期不具合対応（こちらの実装ミスに起因するもの）

【含まれないもの】
・納品後の仕様変更・機能追加（別途お見積り）
・Google / Cloudflare / 各種API提供元の仕様変更に伴う改修
・顧客側の環境変更（アカウント変更・権限変更・プラン変更）に起因する不具合
・顧客が独自に加えた改変後の動作保証
・操作方法の個別レクチャー（マニュアル記載範囲を超えるもの）
・APIの従量課金費用、外部サービスの利用料
```

### 4-2. 免責として必ず書く4項目

1. **外部仕様変更の免責**：Google / Cloudflare / OpenAI 等の仕様変更で動作しなくなる可能性があること、その改修は有償であること
2. **API費用の負担者**：APIキーは顧客名義。従量課金は顧客負担
3. **動的機能の制限**（Cloudflare案件）：会員・EC・予約など静的化できない機能があること
4. **データ責任**：移行・自動化にあたりバックアップを取得するが、最終的なデータ責任は顧客側にあること

### 4-3. 「質問ゼロ化」のためのマニュアル設計

サポートが減らない最大の原因は、マニュアルが**文章だけ**なこと。

- **1操作＝1スクリーンショット**。クリックする箇所は赤枠で囲む
- 章立てを「やりたいこと」で切る（機能名で切らない）
  例：×「トリガー設定」 → ○「毎朝9時に自動で動かしたいとき」
- **エラー別FAQ**を必ず用意する。実際に出るエラーメッセージ文をそのまま見出しにする
  → 顧客はエラー文で検索するので、文言一致が効く
- 短い操作動画（画面録画）を1本添える。文章5ページ分の質問が消える
- 問い合わせ導線を「まずFAQを確認 → 該当がなければ連絡」の順に固定する

**運用ルール**：同じ質問が2回来たら、その場でFAQに追記する。
これを続けると商品が回を追うごとに勝手に強くなる。

### 4-4. 見積もり・スコープ管理

- **時間単価で見積もらない。成果物単位・ページ数単位で見積もる**
- 追加要望は必ず「別注文」として起票する（無料で受けない。1回でも受けると基準が崩れる）
- ヒアリングは固定フォーム。通話は有償オプション（または上位プランのみ）
- 「まず相談だけ」への無料対応は、FAQページ / 事前確認シートで代替する

### 4-5. 再現性を高める仕組み

- 自分用の**テンプレートリポジトリ／マスターシート**を持ち、案件ごとに複製して使う
- 顧客ごとの差分は「設定シート1枚」に閉じ込め、コード本体は共通にする
  → 改修が全案件に横展開できる
- 納品済み案件の一覧（顧客・使用バージョン・納品日）を管理し、
  外部仕様変更が起きたときに有償改修の提案先リストとして使う

### 4-6. やらないことリスト

- 顧客のサーバー・アカウントの**長期的な管理責任**を負う契約
- 相場より安い「お試し価格」の常態化（レビュー獲得の初期のみ、期間を区切る）
- 仕様が固まっていない状態での着手
- 動的機能満載のWordPressを無理に静的化すること
- 自分のAPIキーを顧客ツールに埋め込むこと
